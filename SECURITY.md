# Security Policy

## Supported Versions

Security fixes are applied on `main`.

Older commits, tags, or unpublished local revisions should be treated as
unsupported unless the maintainer explicitly states otherwise.

## Reporting A Vulnerability

Do not open a public GitHub issue for a suspected security problem.

Instead:

1. Use GitHub private vulnerability reporting for this repository if it is available.
2. Otherwise, contact the maintainer privately through GitHub.

Include:

- affected crate and version or commit
- impact and attack preconditions
- reproduction steps or proof of concept
- any suggested fix or mitigation if you have one

The goal is to acknowledge reports quickly, reproduce the issue, prepare a fix,
and then disclose publicly once users have a safe update path.
